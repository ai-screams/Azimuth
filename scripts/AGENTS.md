# scripts

## Purpose
Shell scripts for build, run, quality, security and release work. The `Makefile` targets call into these.

## Subdirectories
| Directory | Purpose |
|-----------|---------|
| `dmg/` | DMG background images (`background.png` / `background@2x.png`) — generated by `make-dmg-background.swift`, used by `release.sh` when staging the DMG |

## Key Files
| File | Description |
|------|-------------|
| `build.sh` | `xcodebuild … CODE_SIGNING_ALLOWED=NO build`. **Produces an ad-hoc build → compile/CI checks only** (unsuitable for permission testing) |
| `run.sh` | Builds with Apple Development signing (`CODE_SIGN_STYLE=Automatic`; `DEVELOPMENT_TEAM` can be overridden by env) and launches the `.app`. **Anything that needs a permission must go through this** — a stable designated requirement keeps the TCC grant |
| `harness-sources.sh` | **The single source for what the harness compiles** (`HARNESS_SRC`, `HARNESS_TESTS`). `test.sh` and `coverage.sh` source it, so a new pure file is added in one place. It defines arrays only and carries no `set` line (see below) |
| `test.sh` | Compiles and runs the list from `harness-sources.sh` with `swiftc`. Propagates the exit code |
| `coverage.sh` | Builds and runs the **same list** with `swiftc -profile-generate` and measures llvm-cov line coverage. Gate **≥90%** (adjustable via the `COVERAGE_MIN` env var) |
| `legacy-build-app.sh` | **Legacy branch.** `make legacy-app`: a swiftc-built, signed universal `build/legacy/Azimuth.app` (bundle id `com.aiscream.Azimuth.legacytest`, build `209.0`) for trying on real 10.13–12 hardware, since local Xcode 27 cannot build the target. `SIGN_IDENTITY` picks the certificate. Ends with the signed bundle gate. Not a release path |
| `legacy-bundle-runtime.sh` | **Legacy branch.** `<app> <identity>`: adds the Swift stdlib (toolchain `swift-5.0`) and the back-deployed `libswift_Concurrency` (`swift-5.5`, universal) when missing (Xcode 26.3 builds already carry both; plain swiftc builds do not), then re-signs dylibs and app (hardened runtime, timestamp, entitlements kept; identity `-` = ad-hoc for the unsigned CI gate). Sparkle.framework is re-signed inside-out only for `-` (an unsigned Xcode build breaks its seal) or with `--resign-sparkle` (`legacy-build-app.sh`; an argument, not an env var, so it cannot leak into a release); a release export's Sparkle is left as signed, so a broken seal fails verification instead of being papered over. Without that dylib a pure-Swift object's deallocation kills the app on 10.13 |
| `legacy-bundle-gate.sh` | **Legacy branch.** `<app> [--signed]` (any other argument is a usage error): asserts min OS ≤ 10.13.0 (x86_64, numeric compare) / 11.0 (arm64), rpath order `/usr/lib/swift` before `@executable_path/../Frameworks` per arch (so 10.14.4+ Intel Macs use the OS runtime), every bundled dylib's x86_64 min OS ≤ 10.13.0, bundled `libswiftCore` and universal `libswift_Concurrency` (presence checked directly — it is weak-linked, so a symbol check alone misses it), universal Sparkle, universal executable, zero unresolved non-weak Swift symbols per architecture (only `@rpath` libraries — on arm64 the OS supplies all but `libswift_Concurrency`). `--signed` adds `CFBundleVersion` 209.N (only release/test builds get it), deep verify, Developer ID authority, team, hardened runtime on the app and every dylib |
| `legacy-version-order.sh` | **Legacy branch.** `<candidate build> <Sparkle framework dir> <tag>`: with Sparkle's own comparator (`legacy-sparkle-compare.swift`), asserts previous legacy (live `legacy-feed` appcast; 404 = first release) < candidate < live main appcast. Equal passes only as a re-run of the same tag (the live feed's download URL points at `<tag>`); another tag reusing N is rejected, since Sparkle would not offer it. Feed URLs are read from `UpdateFeed.swift`. Run by `release-legacy.yml` |
| `legacy-sparkle-compare.swift` | **Legacy branch.** Tiny CLI over `SUStandardVersionComparator` (`A B` → -1/0/1), compiled by `legacy-version-order.sh` against the pinned Sparkle |
| `legacy-appcast-finalize.py` | **Legacy branch.** `<appcast> <repo> <tag>`: rewrites every item's `minimumSystemVersion` 10.13.0 / `maximumSystemVersion` 12.99.99 (the second guard — 13+ never gets a legacy item even if feed switching fails) plus the release-notes link (whole lines, so a second run is byte-identical), then asserts all three. The feed is unsigned, so post-editing is safe |
| `legacy-swift-flags.sh` | **Legacy branch.** Sourced (no `set` lines), defines `LEGACY_SWIFT_FLAGS` — the single copy of the project's Swift language settings (`SWIFT_VERSION`, MainActor default isolation, approachable-concurrency features, member import visibility) for `legacy-check.sh` and `legacy-build-app.sh`. Change it together with the Swift settings in `project.pbxproj` |
| `legacy-sparkle-pin.sh` | **Legacy branch.** Asserts the project requires Sparkle `exactVersion 2.9.3` and `Package.resolved` pins revision `d46d456…` (2.10+ needs macOS 12). Run by `ci.yml` and `release-legacy.yml` |
| `legacy-check.sh` | **Legacy branch.** `make legacy-check`: per-file typecheck of every source at x86_64 macOS 10.13 and arm64 macOS 11 (`-primary-file`, so one failing file cannot hide the rest), then an x86_64 10.13 link against the resolved Sparkle 2.9.3 xcframework. Needed because local Xcode 27 rejects deployment targets below 12.0 |
| `lint.sh` | `swiftlint lint --strict --no-cache --config .swiftlint.yml` |
| `format.sh` | Runs SwiftFormat |
| `secret-scan.sh` | gitleaks secret scan |
| `install-hooks.sh` | Installs `.githooks/pre-commit` as the git hooks path |

## For AI Agents

### Working In This Directory
- **The `build` vs `run` distinction is the important one.** `build.sh` is ad-hoc (its cdhash keeps changing, which breaks the TCC grant); `run.sh` is stably signed. Verify permission-dependent behavior with `make run`.
- `run.sh` reads the product path from the build settings (`BUILT_PRODUCTS_DIR` / `FULL_PRODUCT_NAME`) — never hardcode it.
- Keep the script pattern: `set -euo pipefail` (`test.sh` and `coverage.sh` use `-uo` so they can preserve the exit code) and paths relative to `ROOT_DIR`.
- `harness-sources.sh` **defines arrays only — do not add a `set` line.** `source` runs in the caller's shell, so `-e` would be injected into both scripts and silently break the deliberate choice above.

### Testing Requirements
- After a change, run the matching `make` target directly and confirm the behavior.

### Common Patterns
- zsh, with the root pinned by `ROOT_DIR="$(cd "$(dirname "$0")/.." && pwd)"`.
