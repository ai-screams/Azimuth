Features

Everything in one modifier layer.

Nine kinds of command, 34 shortcuts. No scenes. No automation. Just a reliable spatial grammar for your windows.

Halves & snap-throw

Snap a window to a screen half. Press the same edge again to throw it to the adjacent display, landing in the opposite half.

Thirds & two-thirds

Left/center/right and top/middle/bottom — horizontal and vertical. Axis-independent, so they compose freely.

Maximize / Center

Maximize fills the work area (minus menu bar and Dock); Maximize with gaps leaves a uniform inset on all sides. Center keeps the current size and places the window in the middle.

Move (keep size)

Nudge the window one step in any direction — by its own width or height — clamped at the work-area edge. Never resizes, never changes display.

Relative shrink

Shrink the window to ½ or ⅔ of its current size against a pinned edge — based on the window, not the screen. Effects compose: ⅔ then ½ lands on ⅓.

Move to next display

Send the window to an adjacent monitor, preserving its shape and relative position. It keeps its pixel size, shrinking proportionally only if it doesn't fit.

Undo

Step back through the window's recent frames — 5 by default, up to 20. Display reconfiguration clears history.

Multi-monitor aware

Position-aware adjacent-display selection: the window goes to the monitor that spatially lines up with where it currently sits.

Two presets

Standard (arrow keys) and Vim (HJKL). Both fully customizable per-command, with conflict warnings and per-command Reset in Settings.

Automatic updates

Azimuth checks for new notarized, signature-verified releases and updates itself (Sparkle); or check on demand.

Command palette

Press ⌃⌥P, type part of a command's name, and press Return. A dashed outline shows where the window will go before you commit.

Menu bar & cheat sheet

Click the menu bar icon for every command as a tile. Hold ⌃⌥ for a moment to see which key does what.

Mechanics

How it works

Three behaviors that define Azimuth's spatial model.

Snap, then throw

First press snaps to the left half. Second press on the same edge throws the window to the adjacent display, landing in the opposite half.

Move clamps at the edge

The window steps by its own width and stops at the work-area boundary. No resize, no display change — just a reliable nudge.

Shape preserved across displays

Move to next display keeps the window's relative position and size. If it doesn't fit, both axes shrink by the same factor, so the aspect ratio never changes.

Getting started

Requirements & install

Download the notarized DMG — no build tools required.

Requirements

  • macOS 14 (Sonoma) or later — on macOS 13, use version 1.7.7, and on macOS 10.13–12 the legacy build (both below). Use the newest macOS your Mac supports.
  • Accessibility permission — Azimuth controls other apps' windows via the Accessibility API. Grant it in System Settings on first launch (macOS 10.13–12: System Preferences).

Install

  1. Download the .dmg from the link below.
  2. Drag Azimuth to your Applications folder.
  3. Launch Azimuth from Applications.
  4. Enable Azimuth in System Settings → Privacy & Security → Accessibility (macOS 10.13–12: System Preferences → Security & Privacy → Privacy → Accessibility).
Download for macOS

The download is Developer ID–signed and notarized by Apple, so it opens without Gatekeeper warnings.

  • macOS 13? Download version 1.7.7, the last version for macOS 13. It gets no further updates.
  • macOS 10.13–12? Download the legacy build (1.7.2 Legacy). It keeps the core features but gets no new ones.

After you upgrade macOS, either one moves to the newest version that macOS can run on its next update check.

FAQ

Frequently asked questions

Why does Azimuth need Accessibility permission?

It moves and resizes other apps' windows via the macOS Accessibility API — the standard mechanism for all window managers. Azimuth does no keylogging and makes no network connection except the Sparkle update check.

Does it work on older macOS?

Yes, with an earlier version. On macOS 13 (Ventura), use version 1.7.7 from Requirements & install: it is the last version for macOS 13 and gets no further updates. On macOS 10.13 (High Sierra) through 12 (Monterey), use the legacy build (1.7.2 Legacy). It keeps the core features (window commands, shortcuts, menu, undo) and most settings, but gets no new ones. Launch at login needs macOS 13 and failure notifications need macOS 10.15. Both update themselves, and after you upgrade macOS their next update check moves them to the newest version that macOS can run. The legacy build was tested on a real Mac with macOS 10.13.6 and in macOS 12 and 13 virtual machines; 10.14–11 have not been tested on real hardware. These macOS versions no longer get Apple security updates, so upgrade if your Mac can.

Can I customize the shortcuts?

Yes — open Settings → Shortcuts. You can set per-command bindings, view conflict warnings, toggle command groups on or off, and switch between Standard (arrow keys) and Vim (HJKL) presets.

How are updates delivered?

In-app via Sparkle — notarized and EdDSA-signature-verified. You can also check on demand from the menu bar icon. If you installed with Homebrew (brew install --cask ai-screams/tap/azimuth), updates still come through Sparkle in the app; brew upgrade will not fight the built-in updater.
